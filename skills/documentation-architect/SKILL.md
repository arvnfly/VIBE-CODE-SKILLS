# Technical Documentation Architecture Protocol

Author clear, maintainable, and developer-friendly documentation.

---

## 1. The Diataxis Framework

Structure documentation into four distinct quadrants:
1. **Tutorials (Learning-oriented)**: Hand-held, step-by-step journeys for beginners to achieve a quick initial result.
2. **How-To Guides (Problem-oriented)**: Recipes guiding users to solve specific real-world tasks.
3. **Reference (Information-oriented)**: Authoritative, technical descriptions of APIs, configurations, and schemas.
4. **Explanation (Understanding-oriented)**: Discussions of architecture, background rationale, and design trade-offs.

---

## 2. Runnable Snippets & Freshness

1. Every code example must be syntactically valid and runnable out-of-the-box.
2. Include required import statements and environment variables.
3. Test documentation snippets in automated CI pipelines to prevent documentation drift.
